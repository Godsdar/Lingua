# Lingua: спокойный интерфейс для любопытных к языку

Дата: 2026-10-16. Статус: исследование и предложения, не новый принятый ADR. Активный репозиторий — `work/lingua-repo/`; прежний checkout не использован как текущая реализация. Изменений frontend, commit и deployment в этой задаче нет.

## Вывод

Рекомендуется развивать существующий `/concept/` как **ночную языковую тетрадь**: крупное предложение, выбранное вхождение, короткое объяснение, выразительная карта связей и доступные источники. Geeky-характер дают точные детали — `lemma`, формы, relation labels, клавиатура, provenance — при спокойной общей композиции. Полировка сейчас полезнее нового UI-фреймворка, постоянного свечения или процедурного леса.

Текущие основания: AGENTS.md, MODEL_PLAYBOOK.md, TREE_AND_ANALYSIS_DESIGN.md, ADR-011; `web/concept/concept.css`, `components/explorers.tsx`. Уже есть Tokyo Night / Light / Graphite, выделение конкретных вхождений, раскрытие языков, selected path, native scroll, scale 75–150%, Motion 320/180 ms. Предложения ниже дополняют эти решения. Историческое Atlas-оформление `/` и минималистичный `/concept/` — разные поверхности, их не следует молча смешивать.

В документации CONCEPT.md сохранились ранние утверждения «нет API», но её раздел Live grammar alpha и текущий playbook уже описывают явный запрос spaCy. Дизайн должен различать live grammar, prepared meaning, curated family и unavailable; не объединять их общим бейджем «AI analysis».

## Три направления для выбора

### A. Night notebook — рекомендация

Tokyo Night на спокойном фоне, одна широкая колонка чтения и один раскрываемый инспектор. Предложение 22–26 px, объяснение 16–17 px, метаданные 12–13 px. Основной текст — системный sans; `ui-monospace` только для `lemma`, `NOUN`, `nsubj` и комбинаций клавиш; реконструкции — читаемый italic serif. Не превращать всю книгу в терминал.

Верхняя полоса: Lingua, текущая рабочая область, компактный theme control. Рядом с вводом одна заметная команда `Analyze sentence`, ограничения/приватность обычным текстом. У результата: `Grammar · spaCy` / `Meaning · prepared` / `Origin · curated` и доступное краткое пояснение. Эти метки описывают источник, а не «качество в процентах».

Характерный момент: выбранное слово получает тонкое подчёркивание и тихую поверхность; в дереве проявляется только его путь, а в инспекторе остаются форма, язык и источник. Эффект ощущается через согласованность трёх областей, без светящегося экрана.

### B. Graphite workbench — альтернатива для частого разбора

Graphite, слева текст/выбранная фраза, справа grammar/origin с возможностью расширить граф. Меньше вертикальных вводных заголовков, больше полезной площади. Метаданные выровнены, тонкие разделители только между смысловыми группами. Не делать набор одинаковых карточек и не добавлять декоративную статистику.

Подходит для сравнения зависимостей и исторических форм в нескольких последовательных действиях. Риск: плотность для новичка. Поэтому default connections — выбранное слово; полный граф остаётся явной опцией. На 390 px возвращается последовательная колонка, инспектор ниже графа.

### C. Light field notes — светлая версия для чтения/преподавания

Нейтральная светлая бумага, тёмный текст, синий выбранный путь и сдержанный тёплый акцент общего предка. Больше воздуха вокруг предложения и форм; та же структура действий и та же семантика. Это тема того же продукта, а не отдельный экран и не возврат к кремово-терракотовому шаблону.

Подходит для долгого чтения, экранного показа и аккуратного экспорта. Выбрать одну основную композицию A или B, а C реализовывать токенами; не строить три независимых приложения.

## Конкретная визуальная полировка

1. **Уменьшить конкуренцию инструментов.** При первом входе видны ввод, основной action, примеры и ясная граница возможностей. Экспорт/полный relation list не обязаны конкурировать с вводом, но доступны после результата. Никакого появления смысловых команд только по hover.
2. **Дать тексту ритм.** Пример стартовых токенов: spacing 4/8/12/16/24/32, line-height 1.6 для объяснения, 1.8 для выбираемого предложения; длина текстового объяснения около 65–75ch. Проверить на двух повторяющихся словах, диакритике и длинном вводе.
3. **Развести состояния формой.** Hover — фон; selected — фон и underline; keyboard focus — внешний контур. Disabled не имитирует unavailable-данные: у неизвестного результата есть текстовая причина и возможное следующее действие.
4. **Сохранить спокойную палитру.** Текущие `--lp-bg`, `--lp-surface`, `--lp-fg`, `--lp-muted`, `--lp-accent` — хорошая граница темы. Добавлять семантический токен только при новом смысле, не по одному цвету для каждого компонента. Не назначать gold любому предупреждению или всем родственникам.
5. **Одна система иконок/штрихов.** Использовать имеющиеся иконки/inline SVG; одинаковые stroke, размер и вертикальное выравнивание. Слова `Entry`, `Relation evidence`, `Save insight`, `Export` сохраняют ясность; стрелка сама по себе не заменяет подпись.

Это предлагаемые параметры прототипа. Они не являются уже измеренной или утверждённой дизайн-системой.

## Дерево как узнаваемый элемент

Рекомендация: ясная историческая линия в основании и умеренная крона настоящих форм. Оставить английскую форму якорем, 2–3 ветви при старте, остальные раскрывать по языку. Не обещать новый уровень живых данных: семьи `water` и `mother` пока курируемые.

- SVG-кривые можно сделать пластичнее небольшим сужением и управляемым изгибом. Layout остаётся детерминированным, подписи — вне стыков. Форма не меняет родители/типы отношений.
- Референс собственного blue-tree владельца использовать для направления/сужения силуэта, а не для числа веток. Пышность без evidence не добавляет исторических фактов. На этом этапе лучше хороший каркас без декоративной листвы.
- Корень снизу, современность сверху. Вертикальная дистанция — пространство раскладки, не шкала лет. `*` — реконструкция; dashed — пропущенные стадии. Не переиспользовать dashed как универсальное «сомнение».
- Выбранный путь выделять толщиной и контрастом. Остальные формы можно успокоить, но не сделать неразличимыми. Выделение не должно требовать прочитать цветовую легенду.
- Сохранять читаемые шрифты и отдельную прокрутку. Для 12 узлов оценивается полный обзор; 40/80 — управляемое раскрытие и фокус. Это контрольные фикстуры плотности, не заявка на реальное покрытие каждого слова.
- Инспектор сохраняет `Entry`, `Relation evidence`, пропущенные стадии и CC BY-SA; «красивое дерево» не служит оправданием удалить источники.

## Движение

Сохранить действующий ADR-011: раскрытие до 320 ms, синтаксическое выделение до 180 ms. Движение объясняет действие пользователя; итоговое состояние доступно сразу, без ожидания окончания сцены.

Удержанные узлы плавно перемещаются; новые появляются с коротким смещением/opacity; сплошная связь может расти по pathLength, dashed — появляется через opacity, сохраняя рисунок. Смена темы не пересоздаёт граф и не перезапускает reveal. Не нужны мигающий caret вне редактора, вечный ветер, точки по линиям, вибрация ошибки, fake-progress или camera fly-through. Текущая функция [useReducedMotion](https://motion.dev/docs/react-use-reduced-motion) позволяет явно отдавать конечное состояние.

## Доступность как часть стиля

Tokyo Night стоит адаптировать по контрасту: обычный текст, источники и meaningful hints — минимум 4.5:1; большой текст может использовать 3:1 в условиях WCAG. Прозрачность secondary labels тоже входит в итоговый контраст. [WCAG contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

Команды и узлы должны иметь достаточно большую область попадания: целиться в 32–40 px для обычных контролов, не ниже базового 24×24 CSS px либо предусмотренных стандартом условий spacing/исключений. Inline text tokens требуют отдельного внимания: не увеличивать их так, чтобы ломалась читаемая строка. [WCAG target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

Клавиатура: видимый `focus-visible`, порядок по чтению, Enter/Space на кнопках, native scroll у графа. Не назначать ARIA tree без соответствующей модели стрелочной навигации. Любая hover-информация доступна при фокусе или в inspector. Полный dependency list и текстовые сведения истории сохраняются. Не объявлять всё содержимое инспектора заново при каждом небольшом движении; живые статусы должны быть короткими.

Для 390 px: верхние инструменты переносятся, предложение не требует горизонтального скролла всей страницы; граф прокручивается внутри своей области, inspector идёт следом. Проверить 200% zoom, все три темы и reduced motion. Отсутствие console errors и успешная сборка не заменяют эту визуальную проверку.

## Как выбрать направление

Показать владельцу A и B на одном и том же предложении и одной семье. Оценивать не только статичный кадр: выбрать повторное вхождение, показать связь, раскрыть родственника, открыть источник, сохранить insight. Предлагаемая пользовательская проверка с пятью добровольцами уже описана текущим interaction design; результаты фиксируются вручную без телеметрии и без несанкционированной рассылки.

Критерий полировки: участник понимает, где сейчас его слово и почему с ним связана выбранная форма, а интерфейс не требует объяснять, куда нажать. До такой проверки утверждать, что редизайн улучшил удержание или usability, рано.

## Передача реализации

Агенту `live_interface` переданы ограниченные рекомендации: спокойные состояния источника/доступности, читаемость secondary controls и видимый keyboard focus; текущие 320/180 ms motion contracts сохраняются. Его scope не расширен. Настоящий документ не разрешает backend changes, новый parser, массовую переработку или deployment.
