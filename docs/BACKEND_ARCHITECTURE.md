# Архитектура backend Lingua

Версия 1, 13 октября 2026. Решение: Node.js 24 LTS + TypeScript + Fastify 5. Подробности выбора — ADR-012. Реализация ниже — первый проверяемый этап, без обещания 100% доступности.

## Границы

```text
Browser / Electron / extension
          ↓ explicit request, only selected sentence/context
Same-origin gateway + user session (future public web integration)
          ↓ service credential, never in browser bundle
Fastify /v1: auth → limits → schema validation → service
          ├─ prepared analysis adapter → curated local data
          └─ optional translation → bulkhead/deadline/circuit → existing providers
```

`server/src/app.ts` — HTTP, схемы, безопасные ответы и жизненный цикл. `analysis.ts` — ответ по языковым слоям. `resilience.ts` — лимиты работы и сбои внешних сервисов. `config.ts` — проверка конфигурации до listen. `src/core/providers.ts` — единственный маршрут к переводчикам. `src/data/reading-fixtures.mjs` — общие подготовленные данные, без зависимости backend от UI.

Сервис не вычисляет координаты деревьев и не выбирает тему. Синтаксис и исторические связи — разные наборы данных. Морфологические признаки не заменяют объяснение смысла. Перевод не создаёт этимологических рёбер.

## HTTP-контракт v1

- `GET /health/live`: процесс отвечает; не проверяет внешние сервисы.
- `GET /health/ready`: сервис принимает запросы; 503 при drain.
- `GET /v1/capabilities`: явно показывает prepared grammar и opt-in translation.
- `GET /v1/openapi.json`: схемы запросов и ответов для клиентов.
- `POST /v1/analysis`: одно предложение, его начало в исходном документе и выбранный диапазон UTF-16; независимые слои meaning, grammar, etymology. Точное совпадение с подготовленными примерами маркируется `prepared`; неподдерживаемый текст возвращает `unavailable`.
- `POST /v1/translation`: текст, from/to; отключён по умолчанию. Включение означает отправку текста провайдеру. Ответ сохраняет имя фактически использованного провайдера.

Лимит предложения — 500 UTF-16 единиц и 50 слов, без молчаливой обрезки. HTTP body ограничен 16 KiB. Selection `[start,end)` относится к переданному предложению; `contextStart` задаёт позицию предложения в документе. Сервер возвращает request ID и document/context identity; клиент обязан отбросить ответ, если документ изменился. Сервер не знает полного документа и не может проверить его существование.

Ошибки: 400 schema/range, 401 auth, 413 body, 415 media type, 429 rate, 503 disabled/busy/circuit/upstream, 504 deadline. Тексты и детали провайдерских ошибок не возвращаются и не записываются в логи. Частичное отсутствие языкового слоя — состояние результата, а не фиктивный успешный анализ.

## Устойчивость первого этапа

- Per-IP limit: 60 запросов/минуту, ограниченный размер локального хранилища ключей. Health probes отдельно. `trustProxy=false`: поддельный X-Forwarded-For не меняет ключ лимита.
- Внешние запросы: максимум 8 одновременно, без очереди; перегрузка → 503 + Retry-After.
- Общий deadline перевода 8 секунд. Отмена клиента и остановка сервиса доходят до fetch. Внутренний timeout отдельного провайдера не расширяет общий бюджет fallback.
- Если адаптер игнорирует AbortSignal, HTTP всё равно завершится по deadline, а его слот остаётся занят до фактического завершения. Это не позволяет тайм-аутам порождать бесконечное число фоновых операций.
- После 3 последовательных сбоев переводческий circuit открывается на 30 секунд; затем допускается одна проверка восстановления. Нет автоматического повтора на уровне gateway; ограниченный fallback остаётся внутри существующего providers.ts.
- SIGTERM/SIGINT: сначала readiness=false, затем отмена внешней работы и Fastify close; предельное время остановки 10 секунд. Оркестратор должен давать больший grace period.
- Логи: request ID, шаблон маршрута, статус и длительность. Не писать тело, query, Authorization, API-ключи, IP или исходный текст. Нет продуктовой телеметрии.

Эти лимиты локальны процессу. Для нескольких реплик нужен общий edge rate limiter; circuit остаётся локальным. Одну реплику за proxy нельзя считать высокой доступностью. CPU-bound parser должен работать в worker/process с лимитом памяти; нельзя грузить модель в event loop HTTP-сервера.

## Защита и данные

Production и любой bind вне loopback не стартуют без service API key длиной не менее 32 символов. Сравнение credentials — constant-time digest. Разработка по умолчанию слушает loopback; ключ можно включить и локально. CORS не разрешён. Health возвращает только статус, OpenAPI/capabilities защищены вместе с /v1.

Для публичного браузера следующий шаг — same-origin gateway с пользовательской сессией/HttpOnly cookie и CSRF-защитой, либо отдельный ограниченный публичный endpoint с edge abuse controls. Service key нельзя класть в VITE_* или localStorage. Это не реализованная система аккаунтов.

Заметки и документы не пишутся на сервер и не кэшируются между пользователями. Источники и CC BY-SA сохраняются. Кэш публичных словарных статей можно добавить отдельно по нормализованному языку/лемме/версии источника. Redis не нужен ради кэша частного текста.

## Развёртывание и критерии production

Сегодня: local Node или Docker, публичное демо продолжает жить на Vercel/Pages. Новый backend не размещается автоматически в оплачиваемом сервисе. Бесплатная платформа со сном не даёт гарантии непрерывной доступности. Vercel static deployment не запускает долгоживущий Node-сервер.

Будущий путь: один OCI image → staging → smoke/load checks → health-based rollout → production; TLS и лимиты на gateway. Для целевого SLO, например 99.9% gateway availability, нужны как минимум измерения, мониторинг, бюджет и согласование допустимой деградации. Это цель для обсуждения, не достигнутая характеристика. Качество parser измеряется отдельно от uptime.

До production: выбрать и оценить живой parser, проверить p95/p99 под ожидаемой конкуренцией и медленным провайдером, проверить память/отмену/завершение, подключить probe/alert без текстов пользователей, настроить секреты и rollback. Добавлять PostgreSQL только при accounts/sync; тогда нужны миграции и проверенное восстановление backup. Очередь — только для длительных заданий, не для короткого интерактивного запроса.
